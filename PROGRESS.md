# PROGRESS — оптимизация прогрузки мира через Distant Horizons

Цель: приблизить скорость прогрузки LOD (DH 3.3.2) к «тысячам чанков/с» без заметной потери визуала и без просадки FPS.
Основа: сравнение с SeedGen 0.8.0 (8 пунктов) + сверка с исходниками DH 3.3.2.

**Правила работы**

1. Один этап = одно изменение = один замер. Не смешивать этапы в одном прогоне.
2. Каждое новое поведение включается флагом (`-Daeroworld.dh<Имя>` и/или ключ в `AeroWorldConfig`, как уже сделано для `dhBorder`, `dhTwoPhase`). Флаг выключен → поведение как сейчас.
3. Код SeedGen не переносится. Берётся только идея; реализация своя, на своих именах и на существующих паттернах Aeroworld (`AeroThroughputLimits`, `AeroHybridStats`, `*SelfCheck`).
4. Не готово, пока нет: замера «до/после», проверки визуала по контрольным точкам, отката через флаг.
5. Приоритет: корректность > сборка > консистентность > скорость (как в общих правилах проекта).

## Что отсеяно после сверки с DH 3.3.2

Эти два пункта из первоначального сравнения в 3.3.2 уже не дают выигрыша. Не делать.

- **Пункт 2 (константа 20 в `canQueueRetrievalNow`).** В 3.3.2 `canQueueRetrievalNow` берёт лимит из `getMaxRetrievalQueueCount()`, а константа `MAX_RETRIEVAL_REQUESTS_PER_THREAD = 20` вшита именно туда. Её уже масштабирует `RetrievalQueueLimitMixin` (QUEUE_SCALE = 4). Остаётся только проверить, что дополнительные условия того же метода не режут очередь (этап 4).
- **Пункт 3, часть про приоритет планировщика.** В 3.3.2 `PriorityTaskPicker` сначала сортирует исполнителей по `priority` (Render Loader 6 выше World Gen 5), и только потом по времени работы. Рендер и так обслуживается первым. Отдельный миксин приоритета не нужен.

4. **Порог рендера (renderYieldQueue 2500) не мешает.** Он срабатывал только в первые секунды. Этап 3 нужен для микролагов (p99.5 = 17–38 fps, то есть кадры 26–59 мс), а не для скорости.
